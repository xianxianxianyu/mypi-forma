# 公开发布前检查

[← README](../README.md)

公开代码、把软件按开源许可证授权、将服务部署到公网，是三个不同的决定。修改 GitHub 可见性不会替代第三方授权，也不会补齐应用安全能力。

## 1. 先确定第三方许可边界

原创代码、文档和 Skill 使用 MIT。`src/vendor/transitions-ui-generation/` 保留 Transitions.dev License，不能重新标记为 MIT。

项目保存的上游许可文本允许将动画用于应用，但禁止将动画集合重新包装为竞争性动画产品；上游完整许可还单列了模板、Starter Kit 和 UI Kit 的分发条件，包括免费分发。**不能仅凭「原始仓库公开」「运行时免费」就推断所有再分发方式都已获授权。**

当前维护者决定（2026 年）：以**应用源码**形式公开本仓库，仅在构建动画用途中使用该运行时，保留原始许可和版权声明，不将其包装为动画库、Motion Pack、模板或 UI Kit。此范围**不**延伸到把本仓库整体重新发布为上述产物；改变发布形态前须重新核对条款。

复核清单：

- [ ] 阅读当前及所使用版本的完整条款，确认本项目作为应用演示、Skill 和未来领域组件集合的分发方式是否适用。
- [ ] 若涉及额外授权/套餐，确认已有授权，或取得权利方书面确认。
- [ ] 若目标是整体采用宽松开源许可，替换受限运行时，并检查历史与已有素材中的再分发问题；不要只是删除版权声明。
- [ ] 保留 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md) 和对应许可证，不使用覆盖全仓库的误导性 MIT 标识。

核验资料：[使用版本的上游 LICENSE](https://github.com/Jakubantalik/transitions.dev/blob/7ec0b0b0b8beb15788a9de68a40ec6be2d5e84b5/LICENSE)、[完整条款](https://transitions.dev/terms.html)。本轮在线条款获取受网络限制，使用了随仓库许可和先前保存的上游文本进行检查；这不替代当前条款确认或法律意见。

## 2. 再检查发布内容

- [ ] 对待发布文件和可达 Git 历史重新做敏感信息扫描；忽略规则不会删除历史中已提交的内容。
- [ ] 检查录屏逐帧内容，只使用合成数据，不含真实客户信息、凭据、私人通知或内部页面。
- [ ] 确认 README 对 Demo、真实模型、当前能力与路线图的描述一致。
- [ ] 分别检查依赖许可证与 `npm audit`；已知漏洞为零不等于完成安全审计。
- [ ] 执行 `npm run check` 与隔离的浏览器测试。
- [ ] 整理可解释、可验证的提交；不要把未检查的日志、原始录像或临时产物一起提交。

## 3. 最后执行公开操作

- [x] 维护者确认最终提交、README 来源/许可说明及演示素材（按上述应用源码范围）。
- [x] 已明确授权推送并将仓库设为 Public。
- [ ] 公网部署另行评估，不直接暴露本地开发服务；仓库公开不等于服务可公网部署。

`package.json` 的 `private: true` 用于防止误发布 npm 包，不影响 GitHub 仓库公开；无需为公开代码而删除它。
